# 개발도구 — 고친 게 진짜 되는지 확인하는 스크립트

CLAUDE.md의 작업 원칙 4번: **"빌드했으면 반드시 실행해서 확인하고 넘긴다."**
그 확인을 눈대중이 아니라 숫자로 하기 위한 도구들입니다.

전부 `python 파일이름` 으로 실행합니다. 아래 순서대로 쓰면 됩니다.

---

## 1. `문장끊기_테스트.py` — 서버 없이, 돈 안 들이고

```bash
python 개발도구/문장끊기_테스트.py
```

`배포빌드/server.py`에서 `Segmenter` 클래스만 꺼내 실행합니다.
서버도 안 띄우고 API도 안 부르므로 **비용 0, 3초**면 끝납니다.

문장 끊는 규칙을 건드렸다면 **가장 먼저 이걸 돌리십시오.** 5가지를 봅니다.

| 검사 | 무엇을 막는가 |
|---|---|
| 한국어 · 마침표가 제때 붙는 경우 | 평소 동작이 망가지지 않았는지 |
| 스페인어 · 마침표 없이 60초 | 자막이 멈추지 않는지, 원문이 그대로 재조합되는지 |
| 말이 멈췄다는 신호(VAD) | 즉시 내보내는지 |
| 인식 결과가 도중에 수정 | 잘못된 단어를 미리 내보내지 않는지 |
| 같은 문장 반복 | 강조 반복이 통째로 사라지지 않는지 |

## 2. `캐시_적중확인.py` — 요금이 새는지

```bash
python 개발도구/캐시_적중확인.py
```

설교 원고를 넣은 프롬프트를 4번 연속 호출해 **캐시가 적중하는지** 봅니다.

```
2회차  캐시기록     0 · 캐시읽기  5345      ← 이렇게 나와야 정상
2회차  캐시기록  5396 · 캐시읽기     0      ← 이러면 요금이 6배로 샌다
```

`translate_and_stream`의 system 블록 순서를 건드렸다면 반드시 돌리십시오.
**변하는 내용(문맥·시각·ID)은 반드시 `cache_control` 블록 뒤에** 있어야 합니다.

> Claude 호출이 4번 일어납니다. 몇 센트 듭니다.

## 3. `엔진_인식비교.py` — 음성인식 정확도

```bash
python 개발도구/엔진_인식비교.py <PCM파일> ko-KR
```

같은 음성을 V1(latest_long)과 chirp_3에 각각 흘려 넣어 **인식 결과를 나란히**
보여줍니다. 번역은 하지 않으므로 **Claude 비용은 0**입니다.

실제 설교 녹음에서 PCM을 뽑는 방법:

```bash
"오디오편집기/tools/ffmpeg.exe" -ss 00:35:00 -t 120 \
  -i "설교녹음.mp3" -ac 1 -ar 16000 -f s16le sermon.pcm -y
```

`-ss` 는 시작 위치입니다. 설교 본문이 나오는 구간을 고르십시오
(예배 녹음이면 보통 30분 이후).

## 4. `자막_시간측정.py` — 실제 프로그램을 통과시켜

```bash
python 개발도구/자막_시간측정.py <PCM파일> ko-KR English v1
python 개발도구/자막_시간측정.py <PCM파일> ko-KR English chirp3
```

**LiveWord가 실행 중이어야 합니다.** 음성을 실제 `/audio` 로 흘려 넣고,
송출 화면(`/stream`)에 자막이 **언제 몇 개** 나오는지 잽니다.

```
최대 공백 6.7초 · 평균 간격 3.5초
```

`최대 공백`이 교인이 화면을 보며 기다리는 최악의 시간입니다.

> 번역이 실제로 일어나므로 2분 음성당 몇십 센트 듭니다.

## 5. `중간결과_빈도측정.py` — 왜 느린지 알고 싶을 때

```bash
python 개발도구/중간결과_빈도측정.py <PCM파일> v1
python 개발도구/중간결과_빈도측정.py <PCM파일> chirp3
```

인식기가 **중간 결과를 얼마나 자주 주는지** 셉니다. 자막 속도의 상한이
여기서 정해집니다.

실측값(2분 설교, 2026-09-06):

```
V1        중간 결과 487회 / 120초  →  0.25초마다
chirp_3   중간 결과  20회 / 120초  →  6.0초마다
```

chirp_3의 자막이 느린 이유가 우리 코드가 아니라 **구글이 결과를 드물게 주기
때문**이라는 것을 이걸로 알아냈습니다. 자막 지연을 줄이려다 막히면 먼저
이걸 재 보십시오.

## 6. `캐시블록_점검.py` — 요금 폭증 구조를 미리 막는다

```bash
python 개발도구/캐시블록_점검.py
```

**API를 부르지 않습니다. 비용 0, 1초.** `2. 캐시_적중확인.py`가 실제 호출로
확인하는 것과 달리, 이건 **소스 구조 자체**를 검사합니다.

`server.py`의 프롬프트 조립 부분만 꺼내 실행한 뒤, **문맥을 바꿔도
캐시 블록까지가 한 글자도 안 변하는지** 확인합니다. 양쪽 `server.py`를 모두 봅니다.

한 시간 예배에 $40이 나온 적이 있습니다. 원인은 문장마다 바뀌는 문맥을
설교 원고(캐시 블록) *앞*에 둔 것이었습니다. 그 구조가 다시 들어오면
여기서 실패합니다.

> `translate_and_stream`을 건드렸다면 **반드시** 돌리십시오.

## 7. `배포ZIP만들기.py` — 릴리스에 올릴 암호 ZIP

```bash
python 개발도구/배포ZIP만들기.py   배포빌드/installer/LiveWord_Setup.exe   배포빌드/installer/LiveWord_Setup_v1.2.zip  '비밀번호'
```

**ZipCrypto** 방식으로 만듭니다. 윈도우 탐색기의 기본 압축 해제는
**AES를 못 풀어서** `0x80004005` 오류가 납니다. 7-Zip 등으로 AES 암호 ZIP을
만들면 받는 분이 열지 못합니다. 실제로 겪은 문제입니다.

파이썬 `zipfile`은 암호 ZIP **읽기만** 되고 쓰기는 안 되므로 직접 구현했습니다.
만든 뒤 스스로 열어 원본과 같은지 검증하고, 다르면 실패로 끝냅니다.

> 비밀번호는 **릴리스 설명에 적지 말고** 따로 전달하십시오.

## 8. `번역모델_비교.py` — 새 번역 모델이 나왔을 때

```bash
python 개발도구/번역모델_비교.py 300 60
```

`로그.txt`에서 가장 최근 예배를 찾아, 실제 입력 60문장을 여러 모델로 다시 번역합니다.
**API를 실제로 불러 약 $0.55, 10분쯤 걸립니다.** 첫 글자까지 걸린 시간·비용을 요약하고,
문장별 번역은 JSON으로 남깁니다. 품질은 사람이 봐야 합니다 — 특히 **주어지지 않은 말을
덧붙이는지**, **안내문을 자막으로 내는지** 볼 것.

2026-09-28에 재서 **Opus 4.8을 유지**했습니다(Sonnet 5는 덧붙임, Opus 5.5는 느림).

## 9. `번역음성_비교.py` — 새 음성 합성이 나왔을 때

```bash
python 개발도구/번역음성_비교.py
```

같은 영어 문장을 지금의 Cloud TTS와 Gemini TTS로 만들어 **합성 시간**을 재고,
들어볼 수 있게 파일로 남깁니다. 비용은 1센트 미만. 음성은 한 번에 하나씩 만들기 때문에
**가장 느린 한 번**이 중요합니다. 2026-09-28에는 Gemini가 한 번 76초가 걸려 유지했습니다.

## 10. `Gemini세션갱신_시험.py` — Gemini 세션 10분 제한 대응을 확인

```bash
python 개발도구/Gemini세션갱신_시험.py <PCM파일> 1200 결과.jsonl
```

`배포빌드/server.py`의 `_gemini_live_loop`와 `Segmenter`를 **서버 없이 그대로** 꺼내 돌립니다.
녹음을 브라우저와 같은 85ms 조각으로 실시간 속도로 넣고, 나가는 문장·세션 갱신·오류를
남깁니다. 번역은 하지 않아 **Gemini 요금(분당 약 $0.009)만** 듭니다. 20분이면 약 $0.18.

결과에서 `"diag"` 줄이 갈아탄 자리입니다. "쉼에서"면 정상입니다.
기다리기 싫으면 `RENEW_AFTER=60`을 앞에 붙이면 갈아타기를 60초로 당겨 봅니다(코드는 그대로).

2026-10-11: 20분 녹음에서 두 번 모두 532초에 쉼에서 갈아탐, 오류 0.

## 11. `Gemini_세션관찰.py` — Gemini가 보내는 것을 날것으로

```bash
python 개발도구/Gemini_세션관찰.py <PCM파일> <초> 결과.jsonl [맞춤어휘.txt]
python 개발도구/Gemini_세션관찰_분석.py 결과1.jsonl,결과2.jsonl 나사로,라사로
```

프로그램 코드를 거치지 않고 Gemini Live에 직접 붙어 **서버가 보내는 모든 신호**(GoAway,
음성 활동, interim, 최종 전사, 연결 종료)를 시각과 함께 남깁니다. 번역 없음, Gemini 요금만.

- **세션 제한을 다시 볼 때**: 초를 600 이상으로. 2026-10-11에 9분 GoAway(50초 남음),
  9분 50초 강제 종료(1008)를 확인했습니다.
- **맞춤 어휘(`adaptation_phrases`)를 시험할 때**: 한 줄에 하나씩 적은 파일을 넷째 인자로.
  2026-10-11 결과: 일부러 틀린 `라사로`는 0/2회(부작용 없음), 올바른 용어는 애매한 첫 음절을
  1회 바로잡음. 그 2분은 이름을 이미 다 맞혀서 판정 불가 — **Gemini가 이름을 틀린 실제
  녹음**으로 다시 재야 합니다.
